# 3. Brand System — Full Specification

### 3.1 Identity

- **Name:** KERUS TOURS & TRAVELLERS — legal/long form; **KERUS** as the masterbrand wordmark; descriptor "Tours & Travellers" in lockup.
- **Positioning statement:** *For travellers, families and organisations moving through Kenya, Kerus Tours & Travellers is the mobility partner that combines Kenyan hospitality with international rental standards — transparent pricing, documented and insured vehicles, and a booking experience built on WhatsApp and web — so every journey begins and ends with certainty.*
- **Promise:** A documented, insured, on-time vehicle — and a human who answers, every time.
- **Mission:** Make hiring a vehicle in Kenya as trustworthy and effortless as booking a flight.
- **Vision:** East Africa's most trusted digitally enabled mobility and travel brand.

### 3.2 Values (bilingual working set)

| Swahili | English | Behaviour |
|---|---|---|
| Uhakika | Certainty | Written confirmations, no surprises |
| Uwazi | Transparency | Prices on the page; conditions disclosed |
| Huduma | Service | <5 min WhatsApp response; humans who care |
| Usalama | Safety | Insured, documented, maintained vehicles |
| Ukuaji | Progress | Measured improvement every month |

### 3.3 Voice & tone

- Clear, warm, competent. Short sentences. No hype, no "world-class!!!" energy, no fake urgency.
- Swahili greetings natural in WhatsApp/Status ("Karibu!"), English primary for web (international audience), bilingual where it adds warmth.
- Numbers and policy language are exact; marketing language is human.

### 3.4 Taglines (shortlist for Rhoda)

1. **"Mwendo wako. Uhakika wetu."** (Your journey. Our certainty.) — primary recommendation
2. "Move with certainty."
3. "Driven by trust. Powered by Kenya."

- Pricing block on every vehicle page: daily/weekly/monthly rate, deposit, mileage policy, insurance note, "check availability" CTA. **No hidden pricing** — the category's #1 trust gap.
- Multilingual: English at launch; Swahili version as Phase 4+ option if analytics justify.

# 8. WhatsApp Commerce Architecture

### 8.1 Stages

| Stage | Tool | Trigger | Capability |
|---|---|---|---|
| 1 (Day 1) | WhatsApp Business App | — | Catalogue (fleet), auto-greeting, quick replies, labels (source, vehicle, status) |
| 2 (Month 2–3) | App + structured playbook | — | Qualification scripts, quote templates, deposit flow, SLA enforcement |
| 3 (Month 4–6) | WhatsApp Business API via BSP | >50 conversations/day or 2+ agents | Shared inbox, automation, template messages, CRM integration |

### 8.2 Conversation architecture (spec)

```
GATE 0 — GREETING (instant, always)
"Karibu Kerus Tours & Travellers 🚙✨
How can we help today?
1️⃣ Self-drive   2️⃣ Chauffeur   3️⃣ Airport transfer
4️⃣ Tours        5️⃣ Corporate   6️⃣ Talk to a person"

GATE 1 — QUALIFY (quick-reply tree)
Self-drive → dates → vehicle class → licence/age → pickup location → passengers
Chauffeur  → dates → route/occasion → passengers → vehicle preference
Transfer   → flight no. → date/time → destination area → passengers
Tours      → interest → dates → group size → budget band
Corporate  → org → need → duration → volume → decision maker

GATE 2 — QUOTE (human + template, < 30 min business hrs)
Structured quote block: vehicle · dates · rate × days · deposit · balance ·
included (insurance, mileage) · next step

GATE 3 — BOOK (human)
Written confirmation → deposit (M-Pesa) → receipt → booking ref → T&Cs link

GATE 4 — PRE-TRIP (automated, Stage 3)
T-2 days reminder (pickup point, docs to carry, payment balance)

GATE 5 — HANDOVER
Photo check-in (exterior/interior, odometer, fuel) via WhatsApp → stored to booking record

GATE 6 — RETURN → REVIEW (automated, Stage 3)
Inspection → thank-you → Google review link (deep link) → referral ask
```

### 8.3 SLAs (internal standard)

| Metric | Standard |
|---|---|
| First response (auto) | < 5 seconds |
| First human response (business hrs 7:00–21:00) | < 5 minutes |
| Quote delivered after qualification | < 30 minutes |
| Follow-up if no reply after quote | 24h, then 72h (gentle, once) |
| Every conversation tagged & logged to CRM | 100% |

### 8.4 Compliance & hygiene

- Personal data handled per Kenya DPA 2019 (ODPC registration required — §12).
- Marketing broadcasts only to opted-in lists; templates approved via API rules; no scraping/unsolicited bulk messaging (platform-ban risk).
- Sensitive documents (ID, licence) requested only after booking intent, stored in CRM with restricted access, deleted per policy.

# 9. CRM Data Model

### 9.1 Entities

**Lead** → source, channel, campaign, entry date, first response time, status
**Contact** → name, phone, email, country, segment (tourist/domestic/corporate/diaspora), consent flags, source of first contact
**Vehicle** → reg, make/model, class, daily/weekly/monthly rate, status (available/booked/maintenance), insurance, tracker
**Booking** → ref, contact, vehicle, start/end, pickup/dropoff, rate, deposit, balance, terms version, status
**Payment** → ref, booking, amount, method (M-Pesa code), date, receipt issued
**Review** → contact, booking, platform, rating, text, published date, reply status
**Referral/Partnership** → partner, code/link, bookings attributed, commission status

### 9.2 Pipeline

```
New Lead → Qualified → Quoted → Negotiation → Won(Booked) → In-Trip →
Returned → Reviewed → (Repeat / Dormant)
Dormant → Re-engaged (nurture)
```

### 9.3 Data rules

- One contact per phone number (dedupe on `+254` normalised number).
- Every touch logs: source, timestamp, outcome — "where did this customer come from?" must always be answerable.
- Monthly export to Kerus-owned storage (Google Drive under business account) — data portability guarantee.

# 12. Trust, Legal & Compliance

| Area | Action |
|---|---|
| **Data protection** | Register with ODPC under the Kenya Data Protection Act 2019 (mandatory for businesses processing personal data); publish Privacy Policy; consent checkboxes; data minimisation |
| **Terms & policies** | Terms & Conditions, Booking Policy, Cancellation Policy, Rental Requirements, Payment Policy — drafted by counsel, hosted at /legal/, linked in every booking & quote |
| **Payments** | M-Pesa Paybill with business name (trust signal); receipts for every payment; refund policy explicit |
| **Identity & fraud** | Verification at booking (ID/licence), deposit protects the business, written records protect the customer; never request ID via public channels — only via verified business number |
| **Vehicle records** | Digital check-in/out photos (odometer, fuel, condition) stored with the booking — the single most effective dispute-prevention tool in the industry |
| **Insurance disclosure** | What is covered/excess/what is not — stated on the site and in every quote. (Insurance provider & terms: [TBC] from Kerus) |
| **Reviews integrity** | Only real customers are invited; no incentivised reviews (Google policy); respond to 100% of reviews, especially negative ones |
| **Platform risk** | One backup channel for every primary (email + call beside WhatsApp; social beside Google) — no single-platform dependency |
